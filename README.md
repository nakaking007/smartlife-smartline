# SmartLifeScheduler

## วิธีส่งไฟล์ขึ้นระบบเดิม

1. รวมไฟล์ทั้งหมดลงในโฟลเดอร์ `SmartLifeScheduler`
2. บีบอัดเป็น ZIP

```bash
zip -r SmartLifeScheduler.zip SmartLifeScheduler/
```

3. อัปโหลดเข้าสู่ระบบเดิมผ่านหน้าจัดการที่เคยใช้ เช่น ระบบที่เชื่อมกับ LINE หรือ Google Drive/Server
4. ติดตั้ง dependencies

```bash
npm install
```

5. สร้างผู้ใช้ฐานข้อมูล

ตั้งรหัสผ่านใหม่ผ่าน Environment Variable ก่อน ห้ามเขียนรหัสจริงลงใน repo:

```powershell
$env:SMARTLIFE_DB_PASSWORD="รหัสผ่านใหม่ที่คาดเดายาก"
$env:SMARTLIFE_ADMIN_PASSWORD="รหัสผ่านผู้ดูแลอีกชุดหนึ่ง"
mongosh createSmartlife.js
mongosh createAdmin.js
```

6. รันระบบ

```bash
node server.js
```

7. ทดสอบใน LINE ระบบจะส่งข้อความแจ้งเตือนอัตโนมัติทุกเช้าเวลา 06:00 ตามเวลา `Asia/Bangkok`

## เมนูแก้ไขนัดหมาย

ผู้ใช้สามารถพิมพ์ใน LINE:

```text
เมนูแก้ไข
```

ระบบจะแสดงรายการนัดหมาย พร้อมปุ่ม quick reply สำหรับ `แก้` และ `ลบ`

ถ้าต้องการแผงแก้ไขแบบหน้าเว็บ ให้เปิด:

```text
http://localhost:3000/appointments-panel
```

แผงนี้จะแสดงนัดหมายทั้งหมดที่ยังไม่ถูกลบ พร้อมปุ่ม `แก้ไข`, `บันทึก`, และ `ลบ` ทุกรายการ การแก้ช่องวันเวลาในแผงนี้จะบันทึกและแสดงผลตามเวลาจริงที่ผู้ใช้เลือก โดยตีความเป็นเวลาไทย `Asia/Bangkok` แบบ 24 ชั่วโมง เช่น หากเลือก `15.00 น.` ระบบจะแสดง `15.00 น.` ไม่แปลงเป็น `22.00 น.`

คำสั่งแก้ไขโดยตรง:

```text
แก้นัดหมาย <ID> | ชื่อใหม่ | 2026-05-28 09.00 น. | สถานที่ | ชุด
```

สามารถใช้รูปแบบวันเวลาแบบไทยได้ด้วย:

```text
แก้นัดหมาย <ID> | ชื่อใหม่ | 28-05-2569 : 09.00 น. | สถานที่ | ชุด
```

ตัวอย่าง:

```text
แก้นัดหมาย 6a0fe46ad16ce9833c650bd0 | ประชุมทีม SmartLife | 2026-05-28 10.00 น. | ห้องประชุม | ชุดสุภาพ
```

ตัวอย่างแบบไทย:

```text
แก้นัดหมาย 6a0fe46ad16ce9833c650bd0 | ประชุมทีม SmartLife | 28-05-2569 : 10.00 น. | ห้องประชุม | ชุดสุภาพ
```

คำสั่งลบนัดหมายซ้ำ:

```text
ลบนัดหมาย <ID>
```

หลังจากเปิด `เมนูแก้ไข` หรือ `รายงานวันนี้` สามารถใช้เลขลำดับได้ด้วย:

```text
แก้นัดหมาย 1
ลบนัดหมาย 1
```

คำสั่งตรวจนัดหมายที่อาจซ้ำ:

```text
นัดหมายซ้ำ
```

ระบบจะเปลี่ยนสถานะนัดหมายที่ลบเป็น `deleted` เพื่อป้องกันการลบถาวรโดยไม่ตั้งใจ

## การให้ผู้อื่นใช้งานและความเป็นส่วนตัว

ให้ผู้ใช้ค้นหา LINE Official Account `@426ovxwj` แล้วกดเพิ่มเพื่อน หรือกดปุ่ม `แชร์` ในหน้า SmartLife เพื่อส่งลิงก์เพิ่มเพื่อนให้ผู้อื่น

หน้า `คู่มือ` มี QR Code สำหรับเพิ่มเพื่อนและปุ่มดาวน์โหลดไฟล์ภาพไปแชร์ หากเปลี่ยน LINE Official Account ให้แก้ `LINE_OFFICIAL_ACCOUNT_ID` แล้วรัน `npm run share-qr:generate` ใหม่

หน้า LIFF ส่ง LINE ID token ไปตรวจสอบกับ LINE ที่ฝั่ง server ทุกครั้ง API นัดหมายและ To-do จะใช้ LINE user ID ที่ผ่านการตรวจสอบเท่านั้น ไม่รับ user ID จาก URL หรือข้อมูลที่ผู้ใช้แก้เอง ผู้ใช้จึงดู แก้ หรือลบได้เฉพาะข้อมูลของตนเอง

เมนูด้านล่างมี 5 ส่วน: วันนี้, นัดหมาย, เตือนภัย, ช่วยเหลือ และคู่มือ ผู้ใช้สามารถปิดรายงานเช้า 06:00 หรือเลือกประเภทการเตือนภัยที่ต้องการได้จากหน้าช่วยเหลือ

### วิธีแก้ไขจากปุ่ม

1. กดปุ่ม `แก้ไข` บนการ์ดนัดหมายใน LINE
2. ระบบจะตอบกลับให้ส่งข้อมูลใหม่
3. หากต้องการแก้เฉพาะเวลา ให้พิมพ์เวลาจริงที่ต้องการได้ทันที ตัวอย่างรูปแบบ:

```text
15.00 น.
```

หรือพิมพ์ข้อมูลครบตามรูปแบบ:

```text
ชื่อใหม่ | 28-05-2569 : 09.00 น. | สถานที่ | ชุด
```

ตัวอย่าง:

```text
ประชุมทีม SmartLife | 28-05-2569 : 10.00 น. | ห้องประชุมใหญ่ | ชุดสุภาพ
```

ผลลัพธ์: ระบบจะแก้นัดหมายรายการที่กดไว้ และตอบกลับว่านัดหมายถูกแก้ไขเรียบร้อยแล้ว

### วิธีลบจากปุ่ม

1. กดปุ่ม `ลบ` บนการ์ดนัดหมายใน LINE
2. ระบบจะเปลี่ยนสถานะนัดหมายนั้นเป็น `deleted`
3. ระบบตอบกลับว่า:

```text
เรียน นายท่าน นัดหมายนี้ถูกลบเรียบร้อยแล้วค่ะ
```

หมายเหตุ: ระบบเป็นการลบแบบ soft delete เพื่อป้องกันการลบถาวรโดยไม่ตั้งใจ

### รูปแบบวันเวลาที่รองรับ

ระบบรองรับทั้งรูปแบบสากลและรูปแบบไทย:

```text
2026-05-28 09.00 น.
28-05-2569 : 09.00 น.
28/05/2569 : 09.00 น.
28/05/2569 : 24.00 น.
```

ถ้าใช้ปี พ.ศ. เช่น `2569` ระบบจะแปลงเป็น ค.ศ. `2026` ให้อัตโนมัติ

ระบบตีความวันเวลาที่ผู้ใช้พิมพ์และค่าที่ส่งผ่าน API เป็นเวลาไทย `Asia/Bangkok` และแสดงผลแบบ 24 ชั่วโมงพร้อม `น.` เสมอ แม้ข้อความจะมี `Z` หรือ offset ติดมา จนกว่าจะมีการเพิ่มสถานะเดินทางต่างประเทศในอนาคต ถ้าพิมพ์ `24.00 น.` ระบบจะถือเป็นเที่ยงคืนสิ้นวันนั้น

### ความพร้อมของข้อมูลอากาศ

แหล่งข้อมูลเรียงตามลำดับ: OpenWeather (เมื่อกำหนด API key), Open-Meteo และ MET Norway สำรอง หากแหล่งหนึ่งใช้ไม่ได้จะลองแหล่งถัดไป โดยไม่ปิดการตรวจ TLS มี timeout ต่อแหล่งและแคชรายพิกัดอย่างน้อย 10 นาที (MET Norway เคารพเวลา Expires ของต้นทางด้วย) พร้อมรวมคำขอที่เข้าพร้อมกันเพื่อลดโควตา API ไม่มีการคืนข้อมูลแคชที่หมดอายุเมื่อทุกแหล่งล้มเหลว

MET Norway เป็นข้อมูลจากแบบจำลองพยากรณ์ ไม่ใช่สถานีวัด และอาจไม่มีโอกาสฝน ฝุ่น PM2.5 หรือฝนย้อนหลัง ช่องที่ไม่มีข้อมูลจะแสดง `-` ไม่แทนด้วยศูนย์ แสดงที่มา เวลาแบบจำลอง และเครดิต CC BY 4.0 ในหน้าเว็บ แหล่งสำรองใช้ User-Agent ระบุโครงการตามเงื่อนไขผู้ให้บริการ พิกัดถูกจำกัดทศนิยม 4 ตำแหน่งในการเรียก MET Norway

`GET /api/dashboard` เพิ่ม `weatherStatus` ซึ่งแสดง `available` หรือ `unavailable` และสรุปชื่อแหล่ง/รหัสความผิดพลาดแบบไม่เปิดเผย API key กรณีทุกแหล่งใช้ไม่ได้ยังคืนรายการงานและนัดหมายได้ตามปกติ การตรวจสถานะแอปไม่ถือเป็นการตรวจความพร้อมของทุกผู้ให้บริการ

### ข่าวอุบัติภัยจาก ปภ. (18 ตุลาคม 2569)

- ใช้ข้อมูล GET สาธารณะที่หน้า [DPM Reporter](https://dpmreporter.disaster.go.th/portal/disaster-news) เรียกจริง (`/portal/services/disaster_news/get_news_list.php`) อ่านไม่เกิน 20 รายการล่าสุดของปี และอ่านปีก่อนด้วยเฉพาะวันที่ 1 มกราคม ไม่ใช่ API ที่มีการรับประกันความพร้อมหรือความครอบคลุมทั่วประเทศ
- รับเฉพาะข่าวเผยแพร่ที่ไม่ถูกลบ ประเภทถนน/อัคคีภัย/สารเคมี/อุบัติภัย และเวลาเหตุไม่เกิน 24 ชั่วโมง เวลา `news_date` เป็นเวลาเกิดเหตุตามรายงานในเขตไทย ไม่ใช่เวลาประกาศหรือหลักฐานว่าเหตุยังดำเนินอยู่ เก็บเฉพาะหัวข้อ จังหวัด เวลา และลิงก์ `news_id` ไม่คัดลอกรายละเอียดบุคคลหรือทะเบียนรถ
- ข่าวแสดงเป็น `watch` / “ข่าวติดตาม” (`recordKind=news_report`) และไม่ยกระดับความรุนแรงจากคำในหัวข้อ ข่าวประเภทนี้ไม่เข้า LINE รายงานเช้า แม้ข้อมูลภายหลังระบุ severity สูงขึ้น ส่วนประกาศสำคัญที่ยืนยันระดับเตือนยังใช้เกณฑ์รายงานเช้าเดิม
- ใช้ GDELT เป็นสำรองเฉพาะเมื่อ ปภ. ล้มเหลว ตรวจรูปแบบผลตอบกลับก่อนถือว่าสำเร็จ แหล่งข่าวพักอย่างน้อย 15 นาที รวมคำขอพร้อมกัน และเมื่อผิดพลาดเพิ่มช่วงพักสูงสุด 6 ชั่วโมง โดยรอนานกว่านี้ได้หากมี `Retry-After` ไม่ปิดตรวจใบรับรองและไม่เปลี่ยน IP เพื่อเลี่ยงข้อจำกัด
- `newsSourceStatus` ใน `/api/dashboard`, `/health` และช่องสถานะในเมนูเตือนภัยบอกแหล่งเชื่อมต่อได้/ขัดข้อง/ยังไม่ได้ตรวจรอบใหม่ พร้อมเวลาตรวจ แยกจากจำนวนข่าวที่เข้าเกณฑ์ สถานะสาธารณะไม่มีข้อมูลผู้ใช้หรือข่าวส่วนบุคคล ข่าวเก่ายังคงหมดอายุตามเวลาที่กำหนด ไม่แสดงผลสำเร็จปลอมเมื่อ API คืน HTML หรือข้อความผิดพลาด
- ตรวจด้วย `npm run test:safety` (ข้อมูลสังเคราะห์ในหน่วยทดสอบเท่านั้น ไม่มีการส่ง LINE หรือเขียนฐานข้อมูล) รวมอยู่ใน `npm test`

### แก้การยืนยันตัวตนและการบันทึก (19 ตุลาคม 2569)

- ปุ่มบันทึกพร้อมใช้เมื่อเซิร์ฟเวอร์ยืนยันบัญชี LINE แล้ว หากหมดอายุจะหยุดคำขอและแสดงปุ่มเข้าสู่ระบบใหม่ ไม่ส่งคำขอเขียนเดิมซ้ำอัตโนมัติ
- การเพิ่มงานและนัดหมายกันการกดบันทึกซ้อน หากบันทึกสำเร็จแต่โหลดรายการใหม่ไม่ผ่าน จะบอกว่าบันทึกแล้วและให้กดอัปเดตข้อมูล หากบันทึกล้มเหลวจะเก็บข้อมูลที่กรอกไว้
- แคชผลยืนยัน LINE ไม่เกิน `exp` ของสิทธิ์ตาม [LINE Login API](https://developers.line.biz/en/reference/line-login/#verify-id-token) แยกการหมดอายุ (401) ออกจาก LINE/ฐานข้อมูลขัดข้อง (503) ไม่ส่งรายละเอียดภายในหรือข้อมูลรับรองกลับผู้ใช้
- เมื่อดึงอากาศไม่ได้ รายงานเช้าใช้ `null` สำหรับอุณหภูมิ ฝน และเวลาข้อมูล ไม่สร้างค่าฝนเป็นศูนย์หรือใช้เวลาปัจจุบันแทนเวลาวัด และไม่สรุปว่าไม่มีความเสี่ยงจากข้อมูลที่ขาดหาย
- `npm run test:auth` ใช้ LINE และหน้าจอจำลองเฉพาะในหน่วยทดสอบ รวมกับ `npm test` กรณีนี้ยังไม่ถือว่าได้ทดลองเพิ่มงานจริงผ่านบัญชีผู้ใช้ใน LINE

เงื่อนไขแหล่งข้อมูล: https://api.met.no/doc/TermsOfService และ https://open-meteo.com/en/terms (Free API ของ Open-Meteo จำกัดการใช้งานที่ไม่ใช่เชิงพาณิชย์และจำนวนคำขอ) ไม่มีการสมัครบริการหรือสร้างค่าใช้จ่ายใหม่

### โหมดประหยัดโควตา LINE ฟรี

ค่าเริ่มต้น `SMARTLIFE_NOTIFICATION_MODE=morning-only` ส่งรายงานเช้าสั้น ๆ รวมอากาศ นัดหมาย งานวันนี้ และประกาศสำคัญไม่เกิน 3 เหตุในการส่งเดียวต่อผู้รับ ไม่แนบการ์ดหรือส่งเตือนภัยแยก ปิดการส่งอัตโนมัติก่อนนอน เตือนนัดหมาย งาน และเหตุเร่งด่วนช่วงอื่น เมนูและการเรียกดูข้อมูลเดิมยังใช้ได้

ข้อมูลแผ่นดินไหว พายุฝน และอุบัติภัยยังอัปเดตเบื้องหลังเมื่อบริการตื่นและฐานข้อมูลพร้อม โดยโหมดประหยัดเว้นระยะอย่างน้อย 15 นาที ไม่มีการ push ระหว่างวัน รายงานเช้าเลือกเฉพาะระดับ warning/urgent/critical/emergency ที่ผ่านตัวกรองพื้นที่และประเภทของผู้รับ ข่าวที่พบผ่านดัชนีเว็บไซต์ราชการแสดงเป็น “ข่าวเฝ้าระวัง” ไม่รับรองว่าเป็นการตรวจพบเหตุแบบเรียลไทม์ ไม่มีการเพิ่มคำแนะนำฉุกเฉินที่ไม่อยู่ในประกาศต้นทาง

ก่อนส่ง ระบบอ่าน quota และ consumption จาก LINE โดยใช้เพดานที่ต่ำกว่าระหว่างโควตาจริงกับ 300 ข้อความต่อเดือน คำนวณจำนวนส่งจากยอดคงเหลือและวันคงเหลือในเดือนตาม `Asia/Bangkok` หากผู้รับมากกว่างบประจำวัน จะเลือกผู้รับแบบหมุนเวียนตามยอดใช้โควตา ดังนั้นเมื่อโควตาน้อยบางคนหรือบางวันอาจไม่ได้รับรายงาน

ถ้าโควตาหมดจะบันทึก `deferred / quota_exhausted` และตรวจใหม่วันถัดไป ไม่ลองส่งซ้ำทุกนาที ถ้าตรวจ LINE quota ไม่ได้ จะงดส่งและเว้น 15 นาทีก่อนลองตรวจใหม่ แยกจากสถานะ `success` ซึ่งหมายถึง LINE รับคำขอส่งอย่างน้อยหนึ่งรายการ ไม่ใช่หลักฐานว่าผู้รับอ่านข้อความแล้ว

การส่งใช้ retry key เดิมต่อผู้รับ/วันและ daily lock เดิมเพื่อลดการส่งซ้ำ โควตาที่อ่านได้เป็น snapshot; การส่งจาก OA Manager หรือระบบอื่นอาจใช้โควตาร่วมกัน LINE เป็นผู้บังคับเพดานสุดท้าย จึงไม่ควรมีตัวส่งอัตโนมัติอื่นใช้บัญชีนี้พร้อมกัน

โหมดนี้ไม่เปลี่ยนแพ็กเกจ ไม่ซื้อบริการ และไม่คืนข้อความที่ใช้ไปแล้ว หากใช้ครบเดือนนี้ต้องรอรอบใหม่หรือได้รับคำสั่งซื้อแพ็กเกจแยกต่างหาก การตอบผ่าน Reply API ไม่หักโควตาส่งรายเดือน แต่การใช้ Push จากคำสั่งอื่นยังอาจหักโควตาได้

ตั้ง `SMARTLIFE_NOTIFICATION_MODE=all` เฉพาะเมื่อต้องการคืนการแจ้งเตือนอัตโนมัติแบบเดิม การคืนโค้ดชุดก่อนหน้าหรือเปลี่ยนโหมดไม่ย้อนคืนโควตาที่ใช้แล้ว ไม่มีการเปลี่ยนแปลงข้อมูลนัดหมาย/งาน/การตั้งค่าผู้รับ

ตรวจเฉพาะโหมดประหยัด: `npm run test:morning` ส่วน `npm test` ตรวจ syntax, smoke tests และชุดทดสอบนี้ โดยใช้ test doubles ไม่ส่งข้อความจริงและไม่เชื่อม MongoDB จริง

ทุกเช้าเวลา 06:00 น. ระบบจะแจ้งเองไปที่ LINE โดยรายงานสภาพอากาศและตารางนัดหมาย ไม่ต้องให้ผู้ใช้พิมพ์ถามก่อน

ถ้าเครื่องหรือ server เพิ่งเปิดหลัง 06:00 แต่ยังไม่ถึง 12:00 ระบบจะส่งรายงานเช้าชดเชยครั้งเดียว และบันทึกสถานะใน collection `cron_runs` เพื่อไม่ส่งซ้ำในวันเดียวกัน

## คำถามเรื่องอากาศ

นอกจากรายงานอัตโนมัติทุกเช้าเวลา 06:00 ผู้ใช้ยังสามารถพิมพ์ถามเรื่องอากาศได้โดยตรง เช่น:

```text
วันนี้ฝนจะตกไหม

วันนี้ฝุ่นระดับใด
```

## รายงานที่คงไว้

ระบบยังคงรายงานภาวะฉุกเฉินและเร่งด่วน โดย alert ทั่วไปยังเน้นประเทศไทย ส่วนแผ่นดินไหว พายุ และสึนามิครอบคลุมอาเซียน

ระบบจะ sync เหตุสดจาก USGS/GDACS เข้า collection `alerts` ทุก 15 นาที แล้วตรวจทุก 1 นาทีเพื่อส่ง LINE เมื่อพบ alert ที่ยัง active และยังไม่เคยส่งแจ้งเตือนให้ผู้ใช้นั้น

- แผ่นดินไหวในอาเซียนจาก USGS ขนาด M5.0 ขึ้นไป หรือมี tsunami flag
- พายุ/สึนามิในอาเซียนจาก GDACS เฉพาะระดับสีส้ม/แดง
- รายการซ้ำจะอัปเดต record เดิมด้วย `externalId` เพื่อไม่ส่งซ้ำให้ผู้ใช้เดิม

ระบบจะเตือนภัยธรรมชาติสำคัญเหล่านี้ด้วย:

- ภัยพิบัติ: `disaster`, `natural_disaster`, `ภัยพิบัติ`
- พายุในอาเซียน: `storm`, `thunderstorm`, `typhoon`, `cyclone`, `tropical_storm`, `พายุ`
- แผ่นดินไหวในอาเซียน: `earthquake`, `quake`, `แผ่นดินไหว`
- สึนามิในอาเซียน: `tsunami`, `tidal_wave`, `สึนามิ`, `สึมามิ`, `คลื่นสึนามิ`
- น้ำท่วม: `flood`, `flooding`, `flash_flood`, `น้ำท่วม`

ข้อความแผ่นดินไหวจะรายงานเฉพาะข้อมูลหลัก: เกิดที่ไหน, ขนาดกี่ริกเตอร์, ไกลจาก กทม. กี่กิโลเมตร และอาการที่รับรู้ได้ พายุและสึนามิใช้หลักเดียวกัน โดยไม่ใส่ถ้อยคำให้หลบภัยหรืออพยพในข้อความ LINE เพื่อลดความตื่นตระหนก

## Environment

คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่าจริงก่อนรันระบบ

```bash
MONGODB_URI=mongodb://localhost:27017/smartlife
MONGODB_DNS_SERVERS=8.8.8.8,1.1.1.1
LINE_ACCESS_TOKEN=...
LINE_USER_ID=...
LINE_CHANNEL_SECRET=...
LINE_LOGIN_CHANNEL_ID=...
LINE_OFFICIAL_ACCOUNT_ID=@426ovxwj
LIFF_ID=...
WEATHER_API_KEY=...
CRON_SECRET=...
```

ค่าที่มีคำว่า `SECRET`, `TOKEN`, `PASSWORD` และ API key ต้องตั้งใน Environment Variables ของเครื่องหรือ Render/GitHub Secrets เท่านั้น ห้าม commit ลง repo

หลังสร้าง LIFF ให้ตั้ง Endpoint URL เป็น `https://โดเมนของระบบ/liff/calendar` เปิด scope `openid` และ `profile` แล้วนำ LIFF ID กับ LINE Login Channel ID ไปใส่ใน Environment Variables จากนั้นรัน `npm run rich-menu:setup` หนึ่งครั้งเพื่อสร้างและผูกเมนูด้านล่างกับ LINE Official Account

## สมอง AI ใน LINE

ระบบรองรับการต่อสมอง AI แบบเลือก provider ได้ โดยยังแยกระบบนัดหมายออกจาก AI เพื่อไม่ให้ AI เดาหรือแก้นัดหมายผิดเอง

คำสั่งใน LINE:

```text
สถานะ AI
แปล วันนี้ฉันมีประชุมตอน 15.00 น.
บทความ การเรียนรู้ตลอดชีวิต
สุนทรพจน์ กล่าวเปิดการอบรมครู
```

การตั้งค่าใน `.env`:

```bash
AI_PROVIDER=auto
AI_FALLBACK_PROVIDERS=gemini,groq,openrouter,huggingface,pollinations
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.5-flash
AI_MAX_HISTORY=12

# ทางเลือกอื่นสำหรับแชต/แปล
GROQ_API_KEY=...
GROQ_MODEL=llama-3.1-8b-instant
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=openrouter/free
HF_TOKEN=...
HF_MODEL=deepseek-ai/DeepSeek-V3-0324
POLLINATIONS_API_KEY=...
POLLINATIONS_TEXT_MODEL=openai
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b

PUBLIC_BASE_URL=https://your-public-domain.example.com
LIFF_ID=your_liff_id
```

ตัวเลือกที่แนะนำ:

- `Gemini` เหมาะเป็นค่าเริ่มต้นสำหรับแชตและแปลภาษาไทย เพราะมี free tier และโควตาเริ่มต้นเพียงพอสำหรับทดสอบ
- ถ้าต้องการลองรุ่นใหม่ของ Gemini ให้เปลี่ยน `GEMINI_MODEL` เป็นรุ่น preview ที่บัญชีรองรับ เช่น `gemini-3-flash-preview`; ถ้าเน้นเสถียรให้ใช้ `gemini-2.5-flash`
- `Groq` เหมาะเมื่ออยากได้คำตอบเร็วและมี free plan แต่ต้องดู rate limit ของบัญชีจริง
- `OpenRouter` ตั้ง `OPENROUTER_MODEL=openrouter/free` เพื่อให้ OpenRouter เลือกโมเดลฟรีที่ยังใช้ได้ให้อัตโนมัติ
- `Pollinations Text` ใช้เป็น AI สำรองฟรีได้ แม้ไม่มี key โดยมีข้อจำกัดคิวสาธารณะ
- `Ollama` เหมาะเมื่ออยากรันฟรีในเครื่อง ไม่ส่งข้อความออกนอกเครื่อง แต่ต้องมีเครื่องที่แรงพอ และควรเพิ่ม `ollama` ใน `AI_FALLBACK_PROVIDERS` เฉพาะตอนเปิด Ollama แล้ว
- `Hugging Face Inference Providers` เหมาะสำหรับทดลองหลายโมเดลและใช้ token เดียวผ่าน router ของ Hugging Face

เมื่อใช้ `AI_PROVIDER=auto` ระบบจะลองตามลำดับใน `AI_FALLBACK_PROVIDERS` เฉพาะตัวที่ตั้งค่า key ครบ ถ้าตัวแรกหมดโควตา ล่ม หรือ timeout จะข้ามไปตัวถัดไปโดยอัตโนมัติ


## ปรับแชทและเตือนภัย 12 ตุลาคม 2569

- เมนู LINE ขนาด 2500 × 1686 แบบ 6 ช่อง ใช้ช่องเตือนภัยเดิมเพียงช่องเดียว: วันนี้, นัดหมาย, เตือนภัย, คุยกับ AI, ช่วยเหลือ, ตั้งค่า / คู่มือ
- สร้างภาพในเครื่องด้วย `npm run rich-menu:preview`; `npm run rich-menu:setup` จะเผยแพร่เมนูเป็นค่าเริ่มต้นของบัญชี LINE จึงใช้เมื่อได้รับคำสั่งให้นำขึ้นจริงเท่านั้น
- AI ตอบภาษาไทยโดยตรง ใช้บริบทแยกผู้ใช้และเรียงข้อความที่ส่งติดกัน พิมพ์ `เริ่มคุยใหม่` เพื่อล้างบริบท ความจำอยู่ในโปรแกรม สูงสุด 24 ชั่วโมงนับจากข้อความล่าสุดและหายเมื่อเริ่มโปรแกรมใหม่
- เพิ่ม CAP โดยตรงจากกรมอุตุนิยมวิทยา: https://www.tmd.go.th/service/rss ใช้วันออกประกาศ พื้นที่ เวลาเริ่มมีผล วันหมดอายุ และ references สำหรับประกาศปรับปรุง/ยกเลิก ไม่แสดงประกาศทดสอบ
- เพิ่มตัวเชื่อม Air4Thai: https://air4thai.pcd.go.th/services/getNewAQI_JSON.php รับเฉพาะข้อมูลสถานีไม่เกิน 6 ชั่วโมงที่ AQI ของ PM2.5 มากกว่า 100 ไม่ตีความค่าดิบเป็นประกาศอพยพ การอ่านจริงจากเครื่องนี้ยังติด `UNABLE_TO_VERIFY_LEAF_SIGNATURE`; ไม่ปิดการตรวจใบรับรอง
- ข่าวราชการจาก GDELT แสดงเป็นข่าวเฝ้าระวัง เวลาเป็นเวลาที่ดัชนีพบข่าว ไม่ใช่เวลาประกาศ ไม่มีเวลาที่ตรวจสอบได้จะไม่นำเข้า
- จังหวัดและประเภทที่เลือกใช้กรองทั้งรายการในหน้าแอปและข้อความแจ้งเตือน ประกาศระดับภูมิภาคหรือพื้นที่ไม่ชัดเจนยังคงแสดงเพื่อไม่ตัดข่าวที่อาจเกี่ยวข้อง สถานีฝุ่นไม่ได้แทนสภาพอากาศทุกจุดในจังหวัด
- การกันซ้ำใช้รหัสประกาศ/สถานีและเวลาเดิม ร่วมกับรายการผู้รับ `sentTo` ที่มีอยู่ การเก็บประกาศและส่ง LINE จริงต้องตรวจในระบบที่เชื่อม MongoDB และ LINE ก่อนเผยแพร่
- ตรวจ `npm test` ครอบคลุมบริบทแชทแยกผู้ใช้ เริ่มคุยใหม่ CAP หมดอายุ/ทดสอบ/ยกเลิก ข้อมูลฝุ่นเก่า การกรองจังหวัด/ประเภท และพื้นที่กดเมนู
- สถานะส่งมอบ: ปรับไฟล์และสร้างภาพในเครื่อง อ่าน CAP สดและทดสอบ AI ตอบภาษาไทยได้ ยังไม่เผยแพร่เมนูหรือรีสตาร์ตบริการจริง
- `npm audit` พบคำเตือนใน dependency เดิม 3 รายการ (ip-address, proxy-addr, sharp); ยังไม่ได้เปลี่ยน dependency เหล่านั้นในงานนี้
